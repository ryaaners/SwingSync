# Manual event review

The local app can mark eight swing events using verified decoded frames, calculate descriptive recording-time tempo, and export a report with event images and correction history. Automatic event inference, pose measurements, shot outcomes and coaching remain unavailable. A manual mark is a user's annotation, not validated event detection.

## Using it

Upload and inspect one recording, then use **Build a swing timeline**. Choose a frame with the slider, previous/next buttons or frame number. Wait for its decoded image, choose an event, and mark it. Save a partial or complete set; marked events must occupy distinct frames in the displayed swing order. Save Address, Top and Impact to compute backswing time, downswing time and their ratio. No universal ideal or practice suggestion is attached to those numbers.

Click a marker to return to its decoded frame and approximately seek video playback. The frame panel is the evidence. Browser start offsets, audio and display rotation can make browser time/orientation differ from the decoder; synchronized playback has not been validated. Images retain stored coded orientation, without guessed anatomical, mirror or rotation changes. A failed/busy frame can be retried, and marking stays disabled until that image loads.

Change a mark and save again to recompute timing. Every save records a revision and its manual event snapshot. A conflicting edit from another tab preserves your unsaved draft and blocks saving; **Reload saved events** fetches current state and explicitly discards the draft. Browser polling does not overwrite dirty marks or roll a newer saved revision backward.

**Open local report** exports one self-contained HTML file. It includes current event PNGs, source and relative timestamps, setup metadata, descriptive timing with evidence/reliability, current/superseded revisions (even after clearing all marks), analysis ID and recording SHA256. Human frame numbers start at1; the report also identifies the zero-based decoded index. Downloaded report copies stay wherever saved after local app deletion. This is an observational manual report, not a trained-model or coaching demonstration.

## Timestamp and validity contract

`PUT /api/analyses/{id}/events` accepts `{expected_revision, events:[{name, frame_index}]}`. Indices/revisions are strict nonnegative integers; names are the eight canonical events. No request-supplied timestamp, confidence or predicted origin is admitted. Unknown fields, duplicate names, reused/reversed frames, invalid/nonfinite values and out-of-range indices fail. Only completed inspected recordings can be edited. SQLite performs revision comparison and update in one transaction; a deleted analysis cannot be recreated by a stale annotation save.

Stored events map each index to actual native presentation time and seconds relative to the first decoded frame. Durations subtract those times, never `index/FPS`. Ratio is `(Top−Address)/(Impact−Top)` in recording time; slow motion or speed ramps can alter physical duration/ratio. No pose observations are fabricated to compute this timestamp arithmetic. Reliability remains unvalidated; observations/advice remain empty.

New inspections fingerprint recording bytes before/after decode. `GET /api/analyses/{id}/frames/{index}` verifies that fingerprint, exact decoded PTS and the complete inspected frame inventory in an isolated45-second subprocess. At most two frame/report decoder requests run concurrently; excess requests get429/retry guidance. PNGs preserve aspect ratio within640pixels on the long edge. Evidence is returned without persistent derived image files. File paths are generated by the app, not supplied by requests. Older uploads without a fingerprint must be uploaded again for frame/annotation evidence; their basic inspection history is retained.

## Verification scope

Tests cover nonzero-start variable PTS, exact decoded image correspondence, strict input rejection including NaN/Infinity, revision conflicts, deletion/restart, changed media, bounded decode/PNG/concurrency, escaped report content and cleared correction history. Frontend tests cover polling/draft/conflict/frame-index semantics; CI runs them with Node24.

Execution007 browser QA used a synthetic nine-frame VFR H.264 clip starting at native5seconds. Address0/Top3/Impact8 yielded0.180/0.920seconds; correcting Top to index5 yielded0.410/0.690seconds and ratio0.594203. Reload/restart and conflict handling were observed; all three exported PNGs were independently compared to source frames0/5/8. This proves software behavior only, not golf event accuracy, pose accuracy, coaching efficacy or a permitted real-golf demo.

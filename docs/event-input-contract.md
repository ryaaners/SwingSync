# Research event-input contract — execution 012

This is a generic local-video **software contract for diagnostic event proposals**. It does not establish uploaded-video accuracy, training-domain compatibility, calibrated reliability or normal app availability. A missing model remains unavailable. The protocol permits arbitrary supported research inputs; its fixed TRAIN clips constrain the parity witness, not every possible research video. No paid API, cloud model or LLM is used.

## What the existing event model actually saw

The official [GolfDB preprocessing source](https://github.com/wmcnally/golfdb/blob/a63b4ce8c0900d09abbe92519223efe16810f5f4/data/preprocess_videos.py) converts normalized source bounding boxes to integer pixels, crops that region, resizes its long edge to160, and pads the other axis to160 with ImageNet-mean BGR values. It writes a new constant-reported-FPS video with OpenCV. Inclusive trim counters and original annotation offsets are documented separately in data-contracts.md. The [upstream README](https://github.com/wmcnally/golfdb/blob/a63b4ce8c0900d09abbe92519223efe16810f5f4/README.md) also requires a user sample to be cropped and cut around one swing.

SwingSync's trained heads used the already preprocessed160-square archive, followed by a different frozen ImageNet V2 backbone transform: decoded RGB uint8 CHW tensor, resize short edge232 with bilinear antialiasing, center crop224, conversion to float and ImageNet normalization. This is deliberately not a replication of the original SwingNet160 transform. Exact tensor order matters: a PIL path or early float conversion is not assumed numerically interchangeable.

The pinned torchvision [MobileNet V2 preset](https://github.com/pytorch/vision/blob/v0.24.1/torchvision/models/mobilenetv2.py#L202), [classification transform](https://github.com/pytorch/vision/blob/v0.24.1/torchvision/transforms/_presets.py#L35) and [functional resize/crop source](https://github.com/pytorch/vision/blob/v0.24.1/torchvision/transforms/functional.py#L353) define the precise operations. With one resize dimension, the short edge becomes232 and the long edge is `int(232*long/short)`. Crop offsets are `int(round((resized_dimension-224)/2))`, including Python's tie rounding. Nine square/landscape/portrait and odd-dimension cases were compared with actual pinned tensor transform execution; these prove geometry bookkeeping only, not model accuracy.

A generic full frame cannot reconstruct the missing original golfer bounding box, earlier padding, video reencoding history or original YouTube timestamps. It receives **no guessed ROI crop, padding removal, mirror correction or rotation** before the fixed backbone transform. For a640×360 raster, resize gives412×232 and crop starts at(94,4), retaining224/412 of the nominal horizontal field. A golfer or club outside that field may be lost. Subject coverage is unvalidated; this geometric description is not a calibrated landmark map and does not represent interpolation-filter support. Unknown color-transfer/HDR/source-domain differences are not validated by an RGB conversion. Passing this contract never promotes domain compatibility.

## Explicit metadata and input admission

The operator supplies face-on or down-the-line view, left/right handedness, nonempty club, local media rights/provenance, source/reencoded timestamp basis, an explicit unmirrored declaration and confirmation that they reviewed a single swing. These fields are declarations, not an inferred golfer identity, a swing detector, proof of mirroring convention, physical timing or validation of capture conditions. Known mirrored or ambiguous inputs are refused. Source means operator-declared source-video PTS; it does not certify that the camera was recording normal physical speed.

Accepted local MP4/MOV/WebM/AVI files have exactly one video stream, explicit square sample aspect, fixed upright coded dimensions at most3840×2160, no unverified display matrix/nonzero rotation, size at most150MiB, at most3600 frames and at most30seconds of declared/observed duration. Native inspection is isolated by the caller in a45-second child process. Codec/container errors are failures, not an invitation to fabricate timestamps or event output. No network protocol is admitted by the demuxer.

Every decoded frame retains zero-based index, native integer PTS, rational time-base numerator/denominator and unchanged float64 seconds. Native times must increase strictly and remain distinct in float64; mixed valid time bases and nonzero/negative origins are preserved. There is no FPS reconstruction, frame sampling, jitter, interpolation or hidden frame dropping. Event timing continues to use these actual source coordinates, not a browser seek or rounded API milliseconds.

Duration uses the PTS span plus a known final decoded-frame duration. If the final duration is unavailable, the result explicitly states a span-only duration bound; it does not infer a final interval from FPS. A known declared/observed duration over30seconds fails. There must be at least two decoded frames. Recording time, particularly for slow-motion/reencoded media, is not physical swing tempo.

## Fixed software parity witness

[experiments/event-input-v1.json](../experiments/event-input-v1.json) binds the historical event contract SHA, root lock, reference64-reset context, CPU/one thread/batch16, both selected best heads, and fixed TRAIN clips0/1 with exact media/cache/catalog hashes. Those two clips contain462 frames but share **one source recording and golfer**; clip1 is annotated slow motion. They are not two independent subjects or a generalization sample. Source images remain in ignored local research storage; rights are not enlarged by a software check.

The declared parity checks compare all newly extracted float32 features bit-for-bit with existing TRAIN features under the same pinned CPU/runtime/batch configuration, preserve every cached actual PTS, and compare reference64-reset probabilities/peaks on the same cached versus freshly computed features. No annotation labels, PCE or held-out evaluation is used to select models, thresholds, frames or decoding. A mismatch is a failed computation check to investigate, not permission to pick a more favorable model/context or silently widen tolerance. Actual completed parity evidence belongs in the execution report; this audit itself did not run model inference.

Both heads use independent per-event class peaks and the pinned NumPy default argsort-last tie behavior. Events may duplicate, reverse or occur where background probability is larger. Forcing eight class peaks does not prove that a video contains a swing. Class softmax values and background dominance are uncalibrated model quantities, not validated confidence. Order/duplicate/background diagnostics must be disclosed; no order repair or quality score is implied. Proposed events are not manual corrections and do not justify automatic measurements, practice advice or shot outcomes.

## Interfaces and limits

`event_input_contract.py` exposes `validate_metadata`, `inspect_input`, `_check_geometry`, `transform_geometry` and the strict `validate_protocol`. It imports PyAV only inside inspection, and imports no Torch or model. The worker is responsible for isolated native decode, exact second-decode correspondence, immutable byte/source/runtime/model identity, one shared expensive-work lock and atomic failed/completed state publication. The contract validator pins protocol bytes and explicitly checks operational model/runtime/context/limit/gate fields; changing the protocol must not silently change execution.

Upstream code/data/model licenses are separate: GolfDB code is CC BY-NC4.0, torchvision code has its own BSD terms, and neither grants rights in third-party media or all trained weights. Official source audit copies, raw videos, caches and checkpoints stay ignored; no upstream code is vendored or license applied automatically to original SwingSync code.

Remaining admission gates are a prospective compatible raw-upload preprocessing/crop study, independent source/view/capture coverage, event-error and order/weak-phase reliability analysis without current-test tuning, original-source/frame correspondence where claimed, browser/audio/display synchronization, pose accuracy and coaching evidence. All normal-app, measurement, outcome and coaching gates remain false. Software parity on identical preprocessed TRAIN pixels is a useful step, not end-to-end golf coaching validation.
